## Context

STM32 Live Watch 是一个 VS Code 扩展，用于实时监视和可视化 STM32 微控制器变量。当前版本（v3.9.3）的图表界面存在以下限制：

1. **页面切换 tab 样式**：使用 `var(--vscode-descriptionForeground, #999)` 作为默认颜色，在深色主题下对比度不足
2. **子变量删除**：`deleteVariable` 方法仅允许删除根变量，子变量删除被阻止
3. **时间窗口**：最大支持 60s，无法满足长时间趋势观察
4. **刷新频率**：最低 100ms（10Hz），无法满足高频采样场景

## Goals / Non-Goals

**Goals:**
- 提升页面切换 tab 的视觉辨识度
- 简化变量管理流程（支持子变量直接删除）
- 扩展图表时间窗口至 120s（2 分钟）
- 支持 50Hz（20ms）高频刷新
- 保持调色板一致性（chart.js 和 chartManager.ts）

**Non-Goals:**
- 不修改图表核心渲染逻辑
- 不改变数据采集机制（仍由 PollScheduler 驱动）
- 不添加新的图表类型（仅优化现有折线图）
- 不修改服务器端代码

## Decisions

### 1. 页面切换 tab 样式优化

**决策**：使用 `var(--vscode-foreground, #cccccc)` 替代 `var(--vscode-descriptionForeground, #999)`，增加字重至 `500`，活动状态使用 `600` 并添加背景色高亮。

**理由**：
- `#cccccc` 在深色主题下对比度更高（WCAG AA 标准）
- 字重增加使文字更清晰
- 背景色高亮提供额外的视觉反馈

**替代方案**：
- 使用自定义颜色变量 → 增加维护成本，不采用
- 使用图标指示活动状态 → 增加复杂度，不采用

### 2. 子变量删除支持

**决策**：新增 `findParentPath` 方法，通过路径前缀匹配找到父变量，然后从缓存中移除子变量。

**理由**：
- 子变量路径格式为 `parentPath.member` 或 `parentPath[index]`
- 通过路径前缀匹配可以准确定位父变量
- 移除子变量缓存后，下次刷新时会自动重新加载

**替代方案**：
- 在树节点上添加"删除"按钮 → 增加 UI 复杂度，不采用
- 使用右键菜单删除 → 需要修改 context menu 配置，增加复杂度

### 3. 时间窗口扩展

**决策**：添加 120s 选项，保持现有选项不变。

**理由**：
- 120s（2 分钟）是常见的观察周期
- 保持向后兼容性
- 不影响现有性能（数据裁剪逻辑已优化）

**替代方案**：
- 添加自定义时间窗口输入 → 增加 UI 复杂度，不采用
- 移除短时间窗口选项 → 可能影响某些用户场景

### 4. 高频刷新支持

**决策**：添加 20ms（50Hz）选项并设为默认。

**理由**：
- 50Hz 是工业监控的常见采样率
- 代码已优化（批量更新、增量 Y 轴计算）
- 用户可随时切换回低频选项

**替代方案**：
- 使用 Web Worker 处理数据 → 增加复杂度，不采用
- 动态调整刷新率 → 增加复杂度，不采用

### 5. 调色板优化

**决策**：使用高饱和度色系替代 Catppuccin 柔和色系。

**理由**：
- 高饱和度颜色在深色背景下更显眼
- 颜色区分度更高，便于多变量对比
- 保持 chart.js 和 chartManager.ts 的一致性

**替代方案**：
- 保持原有调色板 → 无法满足"显眼"需求
- 使用用户自定义调色板 → 增加复杂度，不采用

## Risks / Trade-offs

### 风险 1：50Hz 刷新频率可能导致 CPU 使用率增加

**缓解措施**：
- 代码已优化（批量更新、增量 Y 轴计算、二分查找裁剪）
- 用户可随时切换回低频选项
- 仅在面板可见时采集数据

### 风险 2：子变量删除可能导致数据不一致

**缓解措施**：
- 仅从缓存中移除，不修改底层数据
- 下次刷新时自动重新加载
- 用户可通过重新展开父变量恢复

### 风险 3：高对比度调色板可能在某些主题下过于刺眼

**缓解措施**：
- 使用 VS Code 主题变量作为回退
- 颜色选择考虑了可访问性标准
- 用户可通过 CSS 自定义覆盖

## Migration Plan

无需迁移。所有更改都是向后兼容的：
- 现有配置不受影响
- 新选项为可选
- 默认值保持合理
